Why Blending? (What “Translucency” Means on Screen)
• Translucency: multiple scene locations contribute to one screen-space sample
• Because light contributions are independent, we can sum them (superposition)
• Real-time approximation: draw surfaces separately and “compose” them by blending
• Common cases: glass, smoke/particles, decals, UI overlays

Engineering & Computer Graphics • Lecture 5: Blending • 3/30

Raster Pipeline Context: Depth Test vs. Blending
• Rasteriza on generates fragments → per-fragment tests run (e.g., depth test)
• If the fragment passes visibility tests, it can update the framebuffer
• Blending combines the incoming (source) color with existing (destination) color
• Order matters when blending is enabled: “what was already there” affects the result

Why Transparency Is Hard: Depth + Order Dependence
• With blending, the “correct” result depends on
drawing back-to-front (Painter’s Algorithm)
• If transparent objects write depth, they can
incorrectly block farther transparent objects
• Intersecting/overlapping transparent geometry can
create cycles (no perfect sort)
• We mitigate with: sorting, disabling depth writes, or
approximate OIT methods

OpenGL Controls: Enabling and Configuring Blending
• Enable/disable: glEnable(GL_BLEND) / glDisable(GL_BLEND)
• Choose factors: glBlendFunc(srcFactor, dstFactor)
• Choose equation: glBlendEquation(GL_FUNC_ADD / SUBTRACT / …)
• Advanced: separate RGB/alpha factors (glBlendFuncSeparate) + multiple render targets

The “Over” Operator (Classic Alpha Blending)
• Standard composi ng (source over des na on): d = α·s + (1−α)·d
• Interpret α as *coverage fraction* at the pixel (0..1), not “magic transparency”
• Requires back-to-front rendering (near objects composited over far objects)
• Default for sprites, UI, decals, and many particle systems

Engineering & Computer Graphics • Lecture 5: Blending • 9/30

Alpha as Partial Coverage (Anti-Aliasing Intuition)
• Binary mask (0/1) causes jagged edges with 1 sample per pixel (aliasing)
• Fractional α estimates “how much of this pixel is covered” by the shape
• Filtering/MIP-maps can precompute partial coverage for textures
• Beware correlation: some alpha-to-coverage patterns can look wrong when layers overlap

Engineering & Computer Graphics • Lecture 5: Blending • 10/30

Premultiplied Alpha (Avoiding Halos and Getting Correct
Math)
• Store colors as (αR, αG, αB, α) instead of (R, G, B, α)
• Benefits: fewer multiplies during compositing + avoids
edge fringes (“halos”)
• Blend factors typically: (ONE, ONE_MINUS_SRC_ALPHA)
for premultiplied textures
• Rule of thumb: match your asset format to your blend
mode (don’t premultiply twice)

Common Blend Modes (When to Use Which)
• Alpha “over”: (SRC_ALPHA, ONE_MINUS_SRC_ALPHA) → natural layering/coverage
• Addi ve: (ONE, ONE) → glow, sparks, bloom, lens ﬂare (adds light)
• Multiply-like: (ZERO, SRC_COLOR) on des na on → darkening / transmission tricks
• Pick blend mode to match intent: coverage vs. emission vs. filtering

Pitfalls & Debugging Clues (Theory)
• Overbright overlaps: additive blending or repeated “over” without intent
• Wrong hue: confusing coverage α with transmission (t) or mixing color spaces
• Missing/miscolored shadows: translucency model doesn’t match light transport
• Sorting failures: intersecting transparent geometry creates cyclic occlusion

Practice Step 0 — Enable Depth Testing
• Request a depth buffer when creating the framebuffer/window
• Enable test: glEnable(GL_DEPTH_TEST) and choose glDepthFunc(GL_LESS)
• Clear each frame: glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)
• Verify with two overlapping cubes: nearer cube should always win

Engineering & Computer Graphics • Lecture 5: Blending • 17/30

Practice Step 1 — Opaque Pass (Depth Write ON, Blend OFF)
• Disable blending for opaque geometry (default: GL_BLEND off)
• Depth test ON + depth write ON (glDepthMask(GL_TRUE))
• Render opaque objects in any order (depth test resolves visibility)
• Only after this pass: start rendering transparent objects

Engineering & Computer Graphics • Lecture 5: Blending • 18/30

Practice Step 2 — Classic Alpha Blending (Straight Alpha)
• Enable blending: glEnable(GL_BLEND)
• Blend equation: glBlendEquation(GL_FUNC_ADD)
• Blend factors: glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)
• Test with a semi-transparent quad (α = 0.5) over a colored background

Practice Step 3 — Observe Order Dependence
• Render 3 transparent quads with different colors and α ≈ 0.5
• Change draw order (front-to-back vs back-to-front) and compare results
• Explain the difference using: result depends on the current destination color
• Conclusion: blending is not commuta ve → sort transparent geometry

Engineering & Computer Graphics • Lecture 5: Blending • 20/30

Practice Step 4 — Sort Transparent Objects (Back-to-Front)
• Compute a depth key per object: distance to camera (or view-space z)
• Sort descending (far → near) before rendering transparent objects
• Render transparent after opaque pass (still depth-tested)
• Note: this is object-level sorting (per-triangle sorting is expensive)

Engineering & Computer Graphics • Lecture 5: Blending • 21/30

Practice Step 5 — Keep Depth Test, Disable Depth Writes
• Keep depth testing enabled so transparent fragments behind opaque are rejected
• Disable depth writes during transparent pass: glDepthMask(GL_FALSE)
• Render sorted back-to-front with blending ON
• Restore state after: glDepthMask(GL_TRUE) (avoid “state leaks”)

Practice Step 6 — Premultiplied Alpha (Correct Edges)
• Premultiply RGB by α (offline in asset pipeline, or in shader)
• Switch blend factors: glBlendFunc(GL_ONE, GL_ONE_MINUS_SRC_ALPHA)
• Compare with straight alpha: look at soft edges and mipmapped textures
• Document: what artifact disappeared (e.g., dark/bright fringes)

Practice Step 7 — Additive Blending for Glow/Emission
• Use additive blend to “add light”: glBlendFunc(GL_ONE, GL_ONE)
• Render glow sprites/particles after opaque pass (often with depth writes off)
• Limit intensity to avoid washed-out images (clamp or tone-map later)
• Op onal: blur bright parts and add back → simple bloom eﬀect

Practice Step 8 — Tinted Glass via Destination Modulation
• Goal: background is filtered by transmission color tRGB (like colored glass)
• Pass A: multiply destination by t using BlendFunc(ZERO, SRC_COLOR)
• Pass B: add surface reflection/highlights over it (e.g., SRC_ALPHA, ONE)
• This separates “transmission” (t) from “coverage” (α) for better control

Practice Step 10 — Debug Checklist (Most Common
Mistakes)
• State leaks: forgot to re-enable depth writes or disable blending for later draws
• Wrong asset assumption: straight alpha texture but premultiplied blend (or vice versa)
• Sorting: transparent pass rendered in the wrong order or mixed with opaque draws

Extension Topic: Order-Independent Transparency (OIT) in
Practice
• Sor ng fails for intersec ng transparency → OIT aims to remove order dependence
• Exact OIT often stores per-pixel fragment lists (A-buffer family) — memory-heavy
• Popular approximation: Weighted Blended OIT (single pass, constant memory)
• Takeaway: know when sorting is “good enough” vs. when OIT is needed
