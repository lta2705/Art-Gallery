Why textures and sampling matter
• Textures add detail—but detail + undersampling causes
aliasing (jaggies, moiré, shimmer)
• Rendering is *sampling* a continuous signal (surface
appearance) onto pixels

Key idea: aliasing is not a “bug” in the
texture—it is a mismatch between signal
frequency and sampling rate.

• Texture mapping is a resampling problem, like image scaling:
minification & magnification
• Goal: get stable images in motion using filtering and good
sampling patterns

Texture coordinate functions (UV mapping): what “good” means
• Bijectivity: ideally one-to-one mapping (unless intentionally repeating patterns)
• Size distortion: local scale shouldn’t vary wildly across the surface (consistent proportional ratio)
• Shape distortion: avoid extreme stretching/skewing of local neighborhoods (derivative of φ similar in
different directions)
• Continuity: minimize seams; place unavoidable seams in inconspicuous areas
• For geometry by equation: f(u,v) = (x,y,z) just invert the function: v(u,v) = f-1(x,y,z) result might be good
• For meshes: you can compute coordinates geometrically or store UVs at vertices

Geometric mappings: spherical and cylindrical
• Spherical mapping (latitude/longitude): simple, but high distortion near poles
• Cylindrical mapping: better for column-like shapes; reduces pole-style distortion
• Both introduce a seam where atan2 wraps from +π to −π
• When shapes deviate from ideal sphere/cylinder, distortion varies with distance to center/axis

Wrapping modes and texture-space transforms
• UVs can go outside [0,1]²: handle with *clamp* (edge color) or *wrap/tile* (repeat)
• Wrap uses remainder/modulo indexing; clamp saturates indices to valid range
• Modelers often adjust scale/offset/rotation using a 2D transform matrix MT
• Think of textures as functions defined over the infinite plane (wrapping makes this explicit)

Perspective-correct interpolation (2/2): code
• Carry attributes through the same projective transform as geometry
• Linearly interpolate u/w -> us, v/w ->vs, and 1/w-> ws in screen space using barycentric weights
• Recover u and v per fragment: u = us/ws, v = vs/ws
• This matches the correct world-space interpolation along projected lines/triangles

1 // Given per-vertex (u,v,w) after view-projection but before divide
2 us = a*(u0/w0) + b*(u1/w1) + c*(u2/w2);
3 vs = a*(v0/w0) + b*(v1/w1) + c*(v2/w2);
4 ws = a*(1/w0) + b*(1/w1) + c*(1/w2);
5
6 u = us / ws;
7 v = vs / ws;

Continuity & seams: why vertices sometimes must be duplicated
• Closed surfaces cannot be mapped bijectively and continuously onto one rectangle (topology)
• Triangles crossing a seam can interpolate the “long way” around texture space
• Solution: duplicate vertices at seams (same 3D position, different UVs) instead of sharing
texture coordinate
• This allows clean interpolation on each side and prevents extreme compression/distortion

Texture antialiasing: pixels have *footprints* in texture space
• A pixel value (color) in screen space should be an *area average* over that pixel’s area in
texture space, not a point sample
• Through projection + texture mapping, a pixel area maps to a footprint in texture space
• Footprints vary across the image (distance, view angle) and depend on φ distortions
• Goal: compute filtered texture sample ≈ average of texture over the footprint

Reconstruction (magnification): bilinear interpolation
• When footprint < 1 texel, we magnify: need smooth reconstruction between texels
• Bilinear interpolation reads the 4 neighboring texels and blends by fractional offsets
• High-quality large filters are expensive because texture lookups are irregular
• Hardware texture units accelerate bilinear filtering with dedicated caches
1 Color tex_bilinear(Texture t, float u, float v) {
2 float up = u * t.width - 0.5;
3 float vp = v * t.height - 0.5;
4 int left_point = floor(up), right_point = i0 + 1;
5 int top_point = floor(vp), bot_point = j0 + 1;
6 float f_left = up - left_point, f_top = vp - top_point;
7 float f_right= 1-f_left, f_bot = 1 – f_top
8 return f_left*f_top*t[left_point][top_point]
+ f_left*f_bot*t[left_point][bot_point]
+ f_right*f_top*t[right_point][top_point]
+ f_right*f_bot*tright_point][bot_point]

Choosing mip levels: D ≈ max(|uₓ|, |uᵧ|) and trilinear blending
• Estimate footprint width D in texels (common choice: longest edge length)
• Choose level k ≈ log₂(D) (texels at level k cover width 2ᵏ in level 0)
• Nearest-level sampling causes visible transitions; trilinear blends between k0 and k1
• Limita on: footprints can be elongated → square mip texels can over-blur
Color mipmap_sample_trilinear(Texture
mip[], float u, float v,
matrix J) {
D = max_column_norm(J)
k = log2(D)
k0 = floor(k); k1 = k0 + 1
a = k1 - k; b = 1 - a
c0 = tex_sample_bilinear(mip[k0], u, v)
c1 = tex_sample_bilinear(mip[k1], u, v)
return a*c0 + b*c1
}

Anisotropic filtering: handle elongated footprints at grazing angles
• Grazing angles produce anisotropic footprints (long, thin regions in texture space)
• Basic mipmapping approximates with a square → excessive blur along one direc on
• Anisotropic filtering: pick mip level from the *short* axis, then take multiple taps along the long axis
• Common in GPUs; improves floor/road textures dramatically in real-time rendering
